# One stock, and prices as lists (#560) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The game state holds one `stock` record from good to amount, every price is a short list of `{ good, amount }`, and one module is the only code that pays from the stock or adds to it. Nothing the player sees moves.

**Architecture:** A new `src/stock.ts` owns the goods table (stones and the four materials), the `Stock` record, `Price`, and the only reads and writes that move amounts: `canPay`, `pay`, `add`, `stockMoved`. `Mountain.pocket` and `Mountain.materials` go; `Mountain.stock` takes their place, the shape the save already stores (#558). Each buyable keeps its curve as a stones number (`tierCost`, `upgradeCost`, `boostCost`, `promoteCost`) and gains one `…Price` that returns a `Price`; the buy paths and the shown price on an action use the `Price`.

**Tech Stack:** TypeScript, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-14-fresh-save-content-rows-design.md`, section E.

## Global Constraints

- No number moves: the pacing ledger's days, both labs' rows and every screen stay as on `main`. The ledger's End hash may move only from the state's shape; prove that with the canonical end-world comparison used in #559.
- No two shapes side by side: no `pocket` or `materials` field remains on `Mountain`.
- No slower lab: one generations job timed against `main` (`--seeds 1 --runs 4 --policy checker-6x3 --job checker-6x3:1`).
- `src/workshop.ts`'s material handling is extended into `src/stock.ts`, not copied.
- The save's shape does not change, so no reset.
- On screen, materials are still called materials.

## Review Focus

1. A recipe priced in stones and materials refuses when any one good is short, and pays every good at once.
2. A cancelled craft's refund returns every good it took.
3. A shown price that differs in any good refuses the buy (#367), not only a different stones amount.
4. A move's result reports spent and gained per good, so the dig and vein floats still show the stones alone.
5. Accrual adds the materials dug with the stones, through `add`, at the same amounts as today.

### Task 1: The stock module

**Files:** Create `src/stock.ts`, `src/stock.test.ts`.

**Produces:**

- `GOOD_ROWS` (`as const`): `stones` (from the mountain), `clay`, `iron`, `crystal`, `heartstone` (each from its band, read from `layers`), each with an optional `ceiling`.
- `type GoodId`, `GOOD_IDS`, `type Stock = Readonly<Record<GoodId, number>>`, `EMPTY_STOCK`.
- `type PriceLine = { readonly good: GoodId; readonly amount: number }`, `type Price = readonly PriceLine[]`, `stonesPrice(amount): Price`, `priceAmount(price, good): number`, `samePrice(a, b): boolean`.
- `canPay(stock, price): boolean`, `pay(mountain, price): Mountain` (the same mountain when it cannot pay), `add(mountain, gains: Partial<Stock>): Mountain` (held under a row's ceiling), `stockMoved(before, after): { spent: Stock; gained: Stock }`.
- Tests: each function, two-good prices, a short good refuses, the ceiling holds.

### Task 2: `Mountain.stock`

**Files:** `src/mountain.ts`, `src/save-format.ts`, every reader and writer of `pocket` and `materials`, tests (by script, then by hand), `src/test-fixtures.ts` (`patched` merges `stock`).

- `Mountain.stock: Stock` replaces `pocket` and `materials`. Reads are `mountain.stock.stones`. Every write goes through `pay` or `add`.
- The save reader and writer pass `stock` straight through.

### Task 3: Prices as lists

**Files:** `src/tiers.ts`, `src/upgrades.ts`, `src/boosts.ts`, `src/engineers.ts`, `src/workshop.ts`, `src/economy/actions.ts`, their callers and tests.

- `tierPrice(mountain, id)`, `upgradePrice(mountain, id)` (the stones curve becomes `upgradeCost`), `boostPrice(boost, pricing, k)`, `promotePrice(mountain)` and `recipePrice(id, k)` return a `Price`. `RecipeCost` goes. The refund is a `Price` as well.
- `Action`'s shown `price` on `buyUpgrade` and `promote` is a `Price`, compared with `samePrice`.
- `MoveResult`'s `spent` and `gained` are `Stock`s. The screens read `.stones`.

### Task 4: Docs and proof

- `docs/ARCHITECTURE.md`: the stock, the goods table, `Price`, and the one module that pays.
- Proof: the ledger days and both labs as on `main`, a canonical end-world comparison, the visual check with no shot updated, one lab job timed against `main`.
